## 修正的问题

- 统一选期：项目目录、容器、具体期和期内子目录解析一致；显式 `--phase` 优先；修复子命令覆盖参数、已有期阻止新期初始化等问题。
- 保留隔离：新期独立初始化；单期写入守卫继续阻止直接修改状态、伪造答案和越级产物；普通目录中的等待 hook 放行。
- 检查继承：创建前验证期 ID、父期及路径，错误输入不留下登记；路径不得越出容器。继承列表类型、空列表差异、shared 模式和布尔起点均有校验。
- 对齐轨道：阶段 0 的 next 提示与实际 pass 使用同一轨道；声明起点被省略时进入后继有效阶段。
- 修复快照：各期从项目根目录读取 `source_dirs`，分别保存在本期快照目录。
- 控制输出：继承清单分页；JSON 答案只在 `new` 中输出一次完整内容，非 JSON 与 hook 继续使用文字摘要。
- 保持只读：恢复查询在克隆后缺少 cache 时也不新建目录，不确认答案、不推进阶段。

## 输出字符量对照

对照基线使用本轮开始前保存的差异快照重建；改进前后对同一个临时项目执行命令。单期样本包含当前阶段 100 条已答决策、历史阶段 1000 条已答决策，其中一条备注为 1000 次重复短句，包含零值参数；多期样本包含 30 条显式继承路径。统计完整 stdout 的字符数，包含 JSON 格式和末尾换行。

| 场景 | 改进前 | 改进后 | 结果 |
|---|---:|---:|---|
| 单期完整 context | 6779 | 6793 | 新增继承分页元数据 |
| 同一项目 compact | 2808 | 2850 | 比改进后的完整概览少约 58.0% |
| 同一项目 next JSON | 38981 | 24463 | 减少约 37.2%，100 条完整答案全部保留 |
| 30 条继承的 compact | 8428 | 4043 | 减少约 52.0%，首屏 5 条，其余分页读取 |

这不是 tokenizer 测量，也不是实际模型账单。路径长度、决策内容与格式会影响字符量；不能把这些比例直接视为 token 节省比例。继承首屏缩减也不代表可以略过其余有效约束，仍须按分页入口核对。

独立会话语义恢复未验证：本次完成的是脚本、子进程、临时项目和回环 HTTP 回归，没有用真实设计项目另开模型会话，也没有验证宿主压缩或唤醒能力。
