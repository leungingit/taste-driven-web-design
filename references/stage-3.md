## 3. 视觉发散（阶段 3；快速轨道下在阶段 1 里完成）

开始前：`gate.py check 3`。

制作方案前，核对简报中的意向校准结论与用户确认的参考特征。初始意向仅有文字时，须已完成阶段 1 的补图邀请及带图确认；快速轨道也不能将这一步省略或与尚未确认的方向同时开放。各方案围绕已确认的目标感觉发散，每个方案说明如何体现核心意向；不可仅靠局部科技道具或场景题材宣称匹配，也不把智能体自行添加的电影感等气质写成用户要求。

### 3.1 生成矩阵
先核对已批准的 `scope.json.layout_freedom`、阶段 2 选定结果及当前硬约束。`rearrange/restructure` 按下表做布局发散；`keep` 按下方保留布局分支比较表现力。不能在简报写“固定布局/单一样张”却保留相反的范围和检查规则，也不能把已确认的空间关系自行作废。

若阶段 2 后新增的冻结要求与布局发散冲突，先指出冲突并按 workflow.md 的变更管理取得范围变更批准、回退阶段 0 改为 `keep`；已有明确批准且范围一致时不重复询问。仅冻结部分关系时，在其余获准维度内发散；若没有足够自由度则先解决冲突，不研究脚本寻找绕过方式。不得为过闸手改检查结果或把失败改标为通过。

按**主题力度 × 版式家族**生成 6–9 个方案。允许布局变化时，三档力度的区别首先是**布局**，其次才是样式：

| 力度 | 布局 | 样式与表现形式 | 例子 |
|---|---|---|---|
| **克制** | 与参照布局基本一致（区块位置、比例、阅读顺序不变） | 有明显调整：配色、字体、质感、插图、图标、动效、文案语气 | 同样的顶部导航 + 首屏 + 三列卡片，但整体气质换成主题 |
| **中等** | **布局有调整**：区块重排、比例和层级变化、导航位置变化、栅格改变 | 也不同 | 顶部导航改为侧栏，三列卡片改为两列大卡加横幅 |
| **大胆** | **布局被颠覆**：至少颠覆一项——导航范式、阅读顺序、页面隐喻、交互方式、信息组织 | 完全为主题服务 | 文档流改为可探索的地图 / 时间轴 / 舞台；分页改为单屏横向叙事 |

- 参照布局：改版项目是现状页面，新建项目是灰模。在 variants.html 里放一个 `data-role="reference"` 的模板（改版项目照现状重建关键区块即可），作为比较基准。
- 每个方案写 `data-skeleton`（一句话布局骨架，如「左侧导航｜首屏｜两列卡片｜横幅」）；大胆方案还要写 `data-break`（颠覆了什么）。
- 写完运行 `python3 $SKILL/scripts/variants_check.py`：它渲染每个方案、提取主要布局块，计算与参照的布局相似度（0–1）。要求：克制 ≥ 0.55；中等 ≤ 0.55，且与每个克制方案 ≤ 0.6；大胆 ≤ 0.25，且与每个中等方案 ≤ 0.4。不通过就重做那个方案，不要改标签凑数。结果写 `work/variants/layout-check.json`，闸门 3 读取；variants.html 改过后要重跑。
- **任何一轮都必须至少有一个"大胆"档方案**。三档都要覆盖。
- `layout_freedom: keep`（保留布局）时，克制仍检查与参照的布局一致性，中等和大胆不做布局相似度及 `data-break` 检查，改为在同一布局内拉开表现力：中等改变插图、图标、质感体系；大胆让主题接管整个画面（背景场景、动效叙事、非常规视觉语言）。所有方案仍填 `data-skeleton`，用 `data-note` 说明表现差异及保留关系；数量、三档覆盖、真实样张和用户方向选择均不省略。自动检查不证明表现力已达标，仍由用户看样张验收。
- 检查报告必须对应当前范围与样张；布局自由度改变后重新运行 `variants_check.py`，闸门会拒绝与 scope 不一致的报告。网页布局指标不用于评价游戏场景透视、三维模型精度或动画品质；遇到此类范围先按阶段 0 处理适用边界，不自造验收豁免。
- 不要在用户没说的情况下自行收紧（例如自己加"不改信息层级"）。
- 改版项目：同一份真实或演示数据，方便和 baseline 对照。

### 3.2 所有方案集中在一个页面
- 把 `$SKILL/templates/variants.html` 复制为 `work/variants/variants.html`，每个方案一个 `<template id="V{n}">`（写法见模板顶部说明）。不得拆成多个 HTML 文件。
- 页面自带矩阵总览、单个方案查看（375/768/1440 宽度、←→ 切换）、`#embed=V3` 嵌入模式。
- 每个方案用闸门 2 的区块结构（或 baseline 布局）和真实文案；至少完整实现首屏 + 两个区块 + 页脚。`data-note` 写思路和刻意放弃的特征，`data-traits` 写特征编号。
- 插画、照片优先用 inbox 素材（在 variants.html 里写 `../../media/inbox/...`），没有就用标注过的占位块，不用代码画粗糙替代品。
- 重新发散时在同一文件追加新方案（`data-round="2"`），旧方案保留。

### 3.3 选择
- 建 `multi` 决策"哪些方案喜欢或部分可用"（code-native）：题目级 media 为 `{"type":"html","src":"@/work/variants/variants.html","origin":"rendered","display":"wide"}`；每个选项 media 为 `@/work/variants/variants.html#embed=V3`，`viewport: 1440`。
- 再建依赖它的 `single` 决策"选定主方向"，`role: "direction"`，每个选项标 `intensity`。
- 未选中的方向写进 `work/variants/archive.md`：方案编号、可复用的部分、可能的复用场景。它们是后续的素材。

**闸门 3**（快速轨道为闸门 1）：gate 决策 approve。
