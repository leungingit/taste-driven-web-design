## 1. 创意简报（阶段 1）

开始前：`gate.py check 1`。快速轨道下本阶段同时包含阶段 3（视觉发散），两者一起验收。

### 1.1 收集：由谁、从哪里
- **主收集人是用户**。图片、视频等原始素材放 `media/inbox/`，素材登记表 `record/refs.yaml` 和文字描述 `record/notes.md` 放 record/；用户在对话里给的链接、图片，由智能体归档进去。
- **智能体可补充**，但必须标 `source: agent`；每次补充不超过 3 条；经用户确认后才进入特征表。
- **推荐的外部来源**：网站案例库（Godly、Awwwards、Land-book、Lapa Ninja、SiteInspire）、界面案例库（Mobbin）、视觉灵感（Dribbble、Behance、Are.na、Pinterest）、产品自身的品牌或美术资产。

#### 1.1.1 启动前素材准备（首次开放决策页之前）

本节在首次开放决策页之前执行，不是阶段 1 中途新增的聊天等待点。先检查用户是否已经提供能代表**目标感觉**的可查看图片、截图、视频画面或链接中的具体画面。只有形容词、作品名称、未指明画面的链接，或仅有现状截图时，先在用户可见的对话中邀请补图一轮；已有明确目标参考，或用户已委托找图、明确继续文字时，不重复询问。

邀请应复述用户的核心意向，说明文字可能有多种视觉解释，建议提供 1–3 张接近目标感觉的图片，并请用户随图说明“喜欢哪里、不要哪里”。不强制上传，不要求专业术语，允许多图分别表达材质、空间、色调或界面。示例：

> 你提到“《西部世界》中的未来感、科技感”。在正式开启决策页之前，建议补充 1–3 张接近目标感觉的图片，并说说喜欢哪里、哪些感觉不要。也可以委托我先找最多 3 个候选参考，或明确继续文字探索，之后用带图选项确认理解。

- **准备期**：等待用户补图、委托找图或明确继续文字的真实回复；此时不启动决策服务、不开放题目，也不启动只等待决策文件的 waiter。不能把未回复或超时当作默认选择。可先在对话中确认，初始化后将邀请、用户原话与选择、素材位置写入 `record/notes.md`，同步 `record/progress.md`。收到选择后进入阶段 0，不要求用户再发“继续”。
- **进入阶段 1**：复用准备记录，直接整理内容、拆解参考并制作带图决策，不再聊天询问“补图／找图／继续文字”。准备邀请计入 1.8 的首轮投放，不额外增加阶段或收集轮次。
- **补图与找图**：实际查看用户素材并核对批注，不把图中所有元素都当作偏好。用户委托找图时每次最多 3 条，标 `source: agent`，经带图决策确认后才进入特征表。
- **继续文字**：保留原话，把视觉解释标为“待用户确认”，进入带真实样例的参考拆解或主题隐喻决策，不反复追问；准备路径确认不等于方向确认。
- **已开放决策页的旧流程**：不得退回准备期或重复以聊天邀请收口。已有用户参考或继续路径时直接复用；确实缺少继续路径时，在当前阶段建 `visual: false` 的素材路径单选决策（用户补图／委托找图／继续文字），通知并按运行协议持续等待。后续补充要求在现有决策流程内处理。用户选择补图时说明附件提交方式并继续处理可独立的工作；若宿主确实无法接收或接续，先尝试可用路径，登记具体能力阻塞与所需用户操作，不能以普通等待或补图本身为由结束回合。

### 1.2 参考拆解（每个整体参考必做）
用户用一部影视、一款游戏、一个品牌来描述想要的感觉时，这个参考往往包含多个风格不同的子世界（例如一部电影里同时有霓虹街头、太空舱室内和荒漠外景）。**在做任何方向之前**，为 scope.json 里的每个参考建一个 `role: "reference-breakdown"` 决策：
- 每个子世界一个选项，配 2–3 张真实画面（检索图或用户素材，`sample_kind: "artwork"`）。
- 子世界和画面按用户强调的意向筛选；每个选项说明整体的空间、材质、色调、光线或界面语言如何体现该意向，以及仍待确认的理解。不要仅按作品剧情或场景类型分类，也不能因局部有机器、机械臂就断言整体具备用户所说的未来感、科技感。
- 例如“《西部世界》的未来感、科技感”不能直接等同于西部外景或电影感构图。可用实际画面对比不同科技气质，但“洁净实验空间”“精密制造”等都只是候选解释；用户确认前不写为既定偏好。用户已给图时优先围绕其批注拆解。
- 允许多选组合（`type: multi`），用户在备注里指明实际选项名称与要组合的具体特征；提示不得假定固定选项字母或虚构其特征。
- 结论写进 traits.md，标注来源决策 ID。

### 1.3 数量上下限
| 素材类型 | 下限 | 推荐 | 上限 |
|---|---|---|---|
| 参考网站 | 2 | 3–5 | 8 |
| 情绪板图片 | 0 | 5–15 | 25 |
| 反面参考 | 0 | 1–3 | 5 |
| 动效视频 | 0 | 1–3 | 5（每个 ≤ 30 秒） |
| 已有原型 | 0 | — | 3 |

### 1.4 创意完整度
| 级别 | 必须包含 |
|---|---|
| L1 最低 | 一句话主题隐喻 + 3 个形容词 + ≥ 2 个带批注的参考 + 内容清单 |
| L2 标准（默认） | L1 + 情绪板 + 反面参考 + 约束文件 |
| L3 完整 | L2 + 动效视频 / 已有原型 / 品牌或美术资产 |

未达 L1 不开始。主题只是抽象形容词时，先核对 1.1.1 的启动前准备结论，再建决策提出 3 个具体隐喻，每个配真实参考图并说明与原始意向的对应关系。不能用智能体自行提出的隐喻替代用户原始意向。

### 1.5 素材登记 record/refs.yaml
```yaml
- id: R1
  url: https://example.com
  source: user            # user | agent
  role: target           # target 目标 | negative 反例 | structure 空间/布局依据 | implementation 当前实现
  confirmed_by: D04-ref   # 决策 ID 或用户原话出处；未确认则明确标待确认
  borrow: [color, layout] # color | layout | typography | texture | motion | illustration | tone | interaction
  like: "首屏大字压在插画上的层次感"
  avoid: "下半页卡片太模板化"
  weight: high            # high | mid | low
```
图片命名 `I03_粗颗粒纸张.jpg` 并用 `file` 登记；视频抽帧到 `media/keyframes/` 且用户补一句动效描述；品牌资产标明不可变项并写入 constraints.yaml。

素材职责按用户确认填写；一张图承担多个用途时逐项说明。反例只用于检查应避免的问题，当前运行截图只证明现状，都不能自动成为目标或制作底稿；结构依据不能替代最终画风。旧登记缺职责时，针对当前任务核对原始来源并补齐，不推测也不遍历全部素材。制作前核对所用文件的职责；用户纠正后同步 refs、当前有效简报及 progress，历史错误留作来源记录，不继续与新结论并列生效。

### 1.6 特征表 record/brief/traits.md
| 编号 | 维度 | 特征描述 | 来源 | 权重 |
|---|---|---|---|---|
| T01 | color | 冷蓝主色配浅灰底 | D04-ref=B | high |
| T02 | layout | 不对称分栏、大面积留白 | D05-dir=V3 | high |

每个维度 2–5 条，列出冲突和缺口；冲突和缺口各建一个带样例的决策，不在对话里文字提问。文件末尾写 `同步至闸门：N`。

**图层表**（主题带质感或动效时必填，闸门 4 检查）：把画面分层，逐层定下有无质感、动不动，避免后期才发现"卡片该不该透明""卡面要不要动"。

| 图层 | 质感 | 动效（用 0.10.1 的说法） | 备注 |
|---|---|---|---|
| 背景 | 有：颗粒噪点 | 流动，周期 40s | 失焦时暂停 |
| 容器（卡片、面板） | 无，不透明 | 不动 | 保证数据可读 |
| 数据（图表、数值） | 无 | 脉冲：数值更新时 | — |
| 文字 | 无 | 不动 | — |

**动效规格**（有动效时必填）：每个动效一行，写什么在动、哪种说法、周期、覆盖区域、什么不动（见 0.10.2）。

### 1.8 收集轮次（最多 3 轮）
1. 投放：用户放素材、给主题和形容词；复用 1.1.1 在首次开放决策页前完成的素材与继续路径记录，不在阶段 1 中途重新发起聊天邀请。
2. 整理与决策：产出四个文件初稿；参考拆解 → 冲突与缺口 → 风格问题，按依赖顺序逐个建决策。
3. 确认：更新文件、同步、建 gate 决策。仍未解决的写进 brief.md 的"待定项"，留给方向对比解决。
