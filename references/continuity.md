# 上下文、当前工作记录与恢复

目标：即使没有先前聊天内容，也能从项目记录确定有效要求、当前工作位置、证据和下一步。项目记录负责恢复信息；能否唤醒已结束的回合，仍按 runtime.md 验证宿主能力。

## 记录分工

| 记录 | 职责 |
|---|---|
| `record/state.json`、`gate.py next --json` | 真实阶段、轨道、暂停或阻塞状态、未确认答案及下一步；由脚本维护 |
| `record/brief/` | 当前有效的范围说明、设计结论、内容和约束；相关条目附用户原话来源或决策 ID |
| `record/notes.md` | 对话补充及纠正的来源、状态、替代关系和落实位置；复用已有素材笔记，不覆盖原内容 |
| `record/progress.md` | 当前任务、已核对的进展、剩余工作、相关文件与验证；只保留接续所需内容 |
| 决策原文、`record/summary/`、历史样张 | 可回查证据；摘要用于定位，原始题目、答案和实际样张用于核对 |

不在工作记录里复制全部简报、阶段状态、答案或聊天历史。不用记录中的“已完成”替代检查实际产物，也不用摘要替代完整答案。历史结论保留在证据中，当前简报删除已被推翻的结论。

## 对话补充及时落盘

用户新增限制、纠正理解、改变偏好或说明取舍原因时，在执行依赖它的工作前更新 `record/notes.md`；不等到阶段验收。普通状态询问无需记录。每项使用稳定编号，记录：

```text
编号：N001
来源：用户对话，2026-10-19；原话：“保留这张封面图，颜色可以调整。”
状态：用户已明确
适用范围：仅首页首屏
替代关系：无
落实位置：record/brief/constraints.yaml 的封面图约束；相关产物路径
```

- 状态区分“用户已明确”“待用户决定”“智能体暂定”“已被替代”。不把建议或推测写成用户要求。
- 更新要求时新增条目并引用旧编号；旧条目标明“已被 Nxxx 替代”，不静默抹掉来源或将新旧要求并列为有效约束。
- 同步相关简报、特征或约束；冲突尚未解决时保留待定标记，暂停依赖该结论的工作。影响已通过阶段时先按 workflow.md 的变更管理处理，不能靠修改笔记绕过回退与验收。
- 主要审美选择仍走决策协议；属于已有决策的对话作答仍用 `gate.py record --via chat --quote …` 登记。笔记不等于用户批准，也不自动确认答案。
- 来源只保存必要的原话或准确摘录，不复制无关聊天、凭证或私密配置。

## 当前工作记录的更新时机

新项目由 `gate.py init` 从 `templates/progress.md` 生成 `record/progress.md`。已有或迁移项目若缺失，由智能体参考模板新建；先核对状态和文件，无法确认的项目写“待核对”，不重新初始化，不猜测之前进展。

在完成可验证的小步骤（例如一轮原型修改或一项检查）、进入等待、切换阶段、显式暂停或交接前更新。恢复后发现记录过时也要纠正。等待无变化时不反复改写，不记录每次工具调用。

记录对应阶段、关联决策 ID 和答案原始时间戳、相关源码或样张版本。分别写清：已完成哪些部分、剩余哪些部分、已执行验证及结果、未执行项、下一步具体动作。进入等待时写待答决策 ID；新答案到达后先读取完整内容再更新。

保留当前工作所需内容，将历史依据链接到原记录，避免不断追加成长篇日志。每次重要事件及时保存，不依赖智能体一定能预知压缩时间或准确读取上下文剩余比例。

## 固定恢复顺序

每次启动、上下文压缩后或会话交接时执行：

1. 读取 SKILL.md 的全流程执行契约和本协议；已有可靠上下文时不重复加载无关章节。
2. 在项目根目录运行 `python3 $SKILL/scripts/gate.py context --json`。该命令只列出真实流程、当前及并入阶段的决策路径、待确认答案版本和记录清单；不交付或确认答案，不推进阶段，不展开历史全文。
3. 按清单读取 `scope.json`、当前简报与约束、`notes.md` 中仍有效或待处理的条目、`progress.md`。`exists: false` 表示文件缺失；阶段尚未产出的文档可以缺失，恢复工作记录时按上节重建。
4. 只读 `stage_guides` 所列当前及并入阶段说明，按需读取关联决策的完整题目、答案和实际样张；通过 `history_index` 定位有依赖的历史证据。无需每次读取全部摘要卡、旧日志或所有图片。
5. 对照实际源码、原型及验证记录确认工作位置。随后运行 `gate.py next --json`，按完整答案落实剩余工作并精确 ack，再查询 next。若原记录包含会话 ID，先核查该会话是否仍存活，不直接重复启动 waiter 或服务。

`context` 的输出是查询时快照，之后用户仍可提交新答案。`unacked` 仅为定位索引，不能凭它直接 ack；用 `next` 读取完整答案和当前版本。答案只落实一部分时保持未确认，先检查已做修改，补齐剩余内容后再确认。

记录不一致时分别核对：阶段和轨道以状态机为准；答案以当前原文及版本为准；要求核对来源、替代关系和既有批准范围；进展以实际产物为准。较新的笔记不自动取得回退或验收授权。仍无法消除的歧义向用户澄清，其余不受影响的工作可以继续。

## 恢复验证

脚本回归应使用独立命令行进程，只提供项目根目录，验证：

- 当前工作记录过时，也不会覆盖真实阶段或推进流程。
- 只落实部分的答案在恢复后仍待确认，完整备注、数值和版本可重新读取。
- 旧版本确认不吞掉新答案；完成剩余工作后才能按实际版本确认。
- 缺失工作记录可被定位；合并阶段的说明和决策均可找到；历史全文不混入恢复索引。

脚本通过后，还需在真实设计项目上做一次独立会话人工验证：仅提供项目路径和本协议入口，不提供原聊天，让智能体报告当前任务、有效要求来源、已完成与未完成项及下一步；与原会话记录和实际产物对照。加入一条新要求替代旧要求、一个只落实一半的答案，检查是否正确恢复且不重复执行。未进行这项验证时如实标注“独立会话语义恢复未验证”；脚本测试不能证明模型一定正确理解全部要求。
